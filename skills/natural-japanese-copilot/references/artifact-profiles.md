# 成果物に合わせて書く

自然な日本語のルールは、形式別スキルの代わりにはならない。
ファイルの作り方、テーマ、レイアウト、保存、描画確認は、
その形式に対応するスキルの手順を使う。

## 文書の種類ごとの基準

| 種類 | 読み手が求めるもの | 日本語の整え方 | 削ってはいけないもの |
| --- | --- | --- | --- |
| 説明・ガイド | 何をすればよいか | 動作を示す見出し、順を追った手順 | 前提、権限、注意、失敗時の対応 |
| 報告・提案 | 結論と判断材料 | 結論を早めに示し、根拠をつなぐ | 対象範囲、比較条件、反対材料、不確実性 |
| 仕様・要件 | 解釈がぶれないこと | 用語と構文をそろえる | 規範の強さ、条件、例外、参照番号 |
| 議事録 | 決まったことと未決事項 | 発言、決定、宿題を区別する | 担当者、期限、留保、未合意の状態 |
| メール | 要件と相手への配慮 | 用件を明確にし、関係に合った丁寧さにする | 依頼の強さ、謝罪や約束の有無 |
| スライド | 要点を短時間で理解すること | 短い見出しと説明、図との対応 | 数値の前提、条件、出典 |
| 表・ダッシュボード | 値を取り違えず読めること | 列名、単位、注記をそろえる | 分母、期間、欠損の意味、丸めの条件 |
| UI・エラー表示 | 状態と次にできること | 短く具体的に伝える | 実際の制約、操作の結果、データ消失の注意 |

「結論から」を理由に、翻訳元の章立てや提出書式を無断で変えない。
文書の種類にかかわらず、未決の話を読みやすい「合意事項」に作り替えない。

## Markdown・Word

見出しに内容を持たせるが、規定の章名や要件IDは保つ。
段落は意味のまとまりで分ける。
比較は表、手順は番号付きリストなど、内容に合った構造を使う。

本文以外に、表、図表の説明、脚注、ヘッダー、フッター、
テキストボックス、代替テキストを確認する。
参照番号や脚注記号が、対応する説明と結び付いているかも見る。
リンクの表示文字列は日本語として確認し、リンク先は変えない。

## スライド

スライドは、文章の短さだけでなく見て理解できることが重要。
タイトル、図のラベル、軸、凡例、本文の役割を分ける。
「1枚1メッセージ」は目安であって、条件を削る理由ではない。

重要な条件は、その主張を見る場所に残す。
表示中の主張を誤解させる条件を、話者ノートだけに移さない。
詳細な根拠をノートや補足へ分ける場合も、本文との対応を保つ。
名詞句や体言止めは使ってよい。短くするための英語混じりは避ける。

作成後は、スライド上のテキストと話者ノートを確認する。
改行、文字切れ、フォント、はみ出し、図と注記の位置は描画して確認する。
テキスト検査だけで表示品質を確認したことにしない。

## Excel・表形式の資料

文章の修正とデータの変更を分ける。
セル値、型、数式、名前付き範囲、キーを日本語化のために変えない。
読み手に見えるラベル、列名、注記、グラフタイトル、軸名を整える。

「率」には分母、「増加」には比較期間や基準が必要なことが多い。
素材にある情報を表記し、ない情報を推測で補わない。
空欄、ゼロ、該当なし、未取得を同じ意味として扱わない。
列名を短くすると意味が曖昧になるなら、単位や短い注記を併用する。

## HTML・UI

ラベル、ボタン、説明、ツールチップ、入力例、エラー、
空の状態、成功表示、アクセシブルな名称を確認する。
通常の画面だけでなく、失敗・読み込み中・空データの状態も対象。
コードの識別子や翻訳キーは、見える日本語とは分けて扱う。

「処理に失敗しました」だけで不十分なら、確認できる原因や
次にできる操作を具体的に書く。ただし原因を推測で断定しない。
ボタンの短縮で「保存」と「送信」、「削除」と「非表示」を混同しない。
破壊的な操作の結果を、柔らかい言い方で曖昧にしない。

## 確認対象を、先に一覧にする

成果物を作るときは、文章が載る面を把握する。
同じ数値が複数の場所にある場合は、対象と期間も含めて照合する。
原稿、生成後のファイル、画面の表示が一致しているかを見る。

補助検査にテキストを渡すなら、各面に安定したIDを付ける。
たとえば `slide-03-title`、`slide-03-note`、`table-02-caption`。
IDは、読みやすい日本語に置き換える対象ではない。
面が検査用データに含まれていなければ、検査ツールには見えない。

次は `scripts/review_japanese.py` が読める形式の例。
抽出方法自体は、形式別スキルと利用可能なツールに従う。

```json
{
  "version": 1,
  "surfaces": [
    {
      "id": "slide-03-title",
      "kind": "title",
      "markup": "plain",
      "text": "最大5件のリクエストを再試行"
    },
    {
      "id": "slide-03-body",
      "kind": "body",
      "markup": "plain",
      "text": "キャッシュが無効な場合に限り、各リクエストを1回だけ再試行します。"
    },
    {
      "id": "slide-03-note",
      "kind": "note",
      "markup": "plain",
      "text": "再試行の対象は失敗したリクエストです。"
    }
  ]
}
```

この例は抽出データの形式を示すもので、条件をノートへ隠す推奨ではない。
実際の資料では「失敗したリクエスト」という対象も表示面に残す。
本文以外の面も文体検査する。ただし `kind` が `code` または `quote` の面は、
文字列の保護条件だけを調べ、文体を直す候補にはしない。
