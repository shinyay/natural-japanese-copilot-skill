# 設計

[English](../en/design.md) | [README](../../README.md)

## 目的

`natural-japanese-copilot` は、日本語を単語の置き換えとして作るのでは
なく、読者と用途に合わせて意味を組み立て直すためのAgent Skillです。
優先順位は次のとおりです。

1. 利用者の依頼と出力要件
2. 原文や素材の意味
3. 用語、識別子、文書形式の制約
4. 日本語としての読みやすさ

自然に聞こえても意味が変わる修正は採用しません。

## 対象と対象外

対象:

- 英日翻訳
- 日本語の新規執筆、校正、推敲、要約
- 文書、スライド、表、HTML、UIなどに含まれる日本語
- 条件や数値が多い文章の意味確認

対象外:

- 日本語らしさを数値化すること
- AI判定や検出回避を目的とした書き換え
- 原文にない事実、体験、感情、合意、期限の創作
- 自動的な事実確認、公開、送信、専門家レビュー
- ファイル形式別skillの代替

## 構成

```text
skills/natural-japanese-copilot/
├── SKILL.md
├── LICENSE
├── assets/
│   ├── glossary-template.md
│   └── style-profile-template.md
├── references/
│   ├── artifact-profiles.md
│   ├── japanese-style.md
│   ├── review.md
│   ├── semantic-cases.json
│   └── translation.md
└── scripts/
    └── review_japanese.py
```

| 要素 | 役割 |
| --- | --- |
| `SKILL.md` | 毎回使う優先順位、禁止事項、基本手順 |
| `translation.md` | 原文がある翻訳、校正、要約の判断 |
| `japanese-style.md` | 長めの執筆、翻訳調、文体の判断 |
| `artifact-profiles.md` | 文書、スライド、表、HTML、UIの表示面 |
| `review.md` | 意味と読みやすさを分けた確認方法 |
| `semantic-cases.json` | 人が意味差を確認するpositive / negative cases |
| `assets/*` | 依頼された場合に使う用語集と文体profileの雛形 |
| `review_japanese.py` | 任意利用の読取専用checker |

すべてのreferenceを毎回読み込むのではなく、作業に必要なものだけを
選びます。

## 意味を守る単位

文章全体の印象だけでなく、次の要素を個別に確認します。

| 要素 | 代表的な誤り |
| --- | --- |
| 条件 | “only if”を自動実行の保証に変える |
| 否定 | “not all”を全否定にする |
| 確度 | “may”を予定や決定にする |
| 数値 | 件数と回数を入れ替える |
| 帰属 | 第三者の主張を確認済み事実にする |
| 義務 | 禁止、不要、推奨、許可を取り違える |
| 識別子 | API名やcommand optionを翻訳する |
| 構造 | 条件を表示面からnotesだけへ移す |

短くする場合も、結論を支える条件や不確実性は残します。

## 処理の流れ

### 1. 作業の種類を決める

翻訳、校正、要約、新規執筆、診断を分けます。たとえば校正の依頼で
全文を別の論旨へ書き直しません。

### 2. 読者と成果物を確認する

読者、目的、文体、表示面、逐語指定を確認します。責任や期限が変わる
曖昧さ以外は、合理的な前提で進めます。

### 3. 変えてはいけない情報を特定する

事実、対象、数値、単位、条件、否定、確度、帰属、用語、識別子を
先に拾います。重要文書では面ごとの対応も確認します。

### 4. 日本語として組み立てる

英語の語順をそのまま移さず、意味のまとまりで文を作ります。一方で、
構造や対応関係が要件の場合は勝手に並べ替えません。

### 5. 意味と文体を別々に確認する

まず追加、脱落、強めすぎ、対象の取り違えを確認します。その後、
日本語だけを読み、係り受け、助詞、冗長さ、文脈を確認します。

### 6. 保存された成果物を確認する

見出し、表、図のlabel、脚注、注記、speaker notes、代替text、UI
messageも対象にします。生成前の本文だけを確認して終わりません。

## runtime instructionsが日本語である理由

実行時instructionsは、日本語の助詞、否定、確度、語の組み合わせなどを
直接記述するため日本語で保守します。英語の利用者もskillを選択でき、
英語で依頼できます。公開手順、制限、評価方法は日英両方で提供します。

## 文体規則の考え方

特定の表現を常に禁止しません。たとえば無生物主語、体言止め、
「です・ます」の反復は、文脈に合えば残します。checkerの指摘も
修正命令ではなく、見直し候補です。

新しい規則には次の両方が必要です。

- 変更によって改善するpositive case
- 同じ変更を適用してはいけないnegative case

この組み合わせで、局所的な改善を過度な一般化にしないようにします。

## データと外部操作

skillは静的なinstructionsとreferenceで構成され、本文を外部へ送る
独自機能を持ちません。checkerもローカルファイルを読み取るだけです。
ただし、Copilot環境そのもののデータ処理は、利用中の製品と組織の
設定に従います。詳しくは[Security Policy](../../SECURITY.md)を参照して
ください。
